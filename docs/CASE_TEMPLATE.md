# 案例模板

每个被解剖的 App 建一个案例文件。目标不是写观后感，而是让别人能按同一份证据重做主体。

## 3. 主体清单

每个可交互或承载信息的主体都单独一行，不合并：

| 主体 | 代码名 | 类型 | bounds | 证据 |
|---|---|---|---|---|
| | | 按钮 / Tab / 图标 / 输入 / 列表 / 容器 | | 已证明 / 推断 / 未知 |

主体至少要记录：

- 几何：位置、尺寸、圆角、内边距、间距。
- 视觉：背景、文字、图标、描边、阴影。
- 状态：默认、选中、按下、禁用、明暗主题。
- 行为：点击、长按、滑动、跳转。
- 资源：SVG、PNG、颜色、字体、资源 ID。

## 8. 未知项

只写真正没追到的：

- 未拿到的 Hermes / 原生模块。
- 未观测到的状态。
- 无法确认的动画曲线。
- 无法确认的授权。

不要把“没做”写成“未知”，也不要把“看起来像”写成“已证明”。
